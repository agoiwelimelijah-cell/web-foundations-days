# Course Reflection: Web Foundations, API Engineering & System Design

The most challenging concept in this course was mastering concurrency control and race condition prevention when designing systems for massive flash traffic. In early projects, I assumed database transactions naturally solved concurrent conflicts, but I soon discovered that simultaneous read-then-write patterns cause double-booking and severe data corruption. I overcame this by studying database isolation levels and implementing atomic conditional SQL updates (`UPDATE ... WHERE status = 'AVAILABLE'`) combined with Redis distributed locks. Understanding how single atomic statements eliminate race conditions at the database engine level was a critical breakthrough in my engineering perspective.

Based on feedback received throughout the capstone presentations, the primary area I would improve in my TicketHub architecture is the resilience and observability of asynchronous jobs. While the design uses RabbitMQ for ticket fulfillment, I would add dedicated dead-letter queues, exponential backoff with jitter for payment retries, and distributed tracing via OpenTelemetry to identify bottlenecks across microservices. Furthermore, replacing seat polling with WebSocket channels would deliver instant seat-state updates to clients.

Next, I plan to delve deeper into distributed consensus protocols such as Raft and Paxos, alongside Kubernetes cluster management. Mastering how partitioned databases maintain consistency across multi-region deployments will enable me to build resilient, planetary-scale cloud systems.
